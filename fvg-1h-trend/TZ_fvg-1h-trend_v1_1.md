## 1. Утверждённые решения v1 (зафиксировать, не переделывать)

1. **Зоны — массив объектов (UDT), не параллельные массивы.** Утверждено: индексы не разъезжаются при удалении из середины пула.
2. **Комиссия 0.055%** — стандарт репозитория, сопоставимость с SMC/MSNR/CRT. Остаётся.
3. **process_orders_on_close=false** — утверждено для этой стратегии: входы лимитные, с `true` исполнение было бы оптимистичнее реальности.

Отразить пункты 1–3 в changelog шапки скрипта как «approved v1.1».

## 2. Правка CLAUDE.md репозитория

Чтобы правило `process_orders_on_close=true` не нарушалось молча, добавить в CLAUDE.md исключение (формулировка — примерно):

> process_orders_on_close=true — для стратегий со входом по рынку на закрытии бара.
> **Исключение:** стратегии с лимитными входами используют process_orders_on_close=false — иначе лимитка исполняется по цене закрытия сигнального бара, что оптимистичнее реального исполнения.

Ничего больше в CLAUDE.md не менять.

## 3. Тайм-стоп (новое в коде)

- Input `maxBarsInTrade`, int, **default 0 = выключен**, диапазон 0–500.
- Логика: если позиция открыта ≥ maxBarsInTrade баров — закрытие по рынку на закрытии текущего бара (`strategy.close`), причина в комментарии ордера `time-stop`.
- При `partialTP=true` отсчёт от бара входа, не от частичной фиксации.
- В таблицу метрик добавить счётчик: «закрыто по тайм-стопу: N (X% сделок)».
- Выключенный тайм-стоп не должен менять ни одного результата v1 — проверить: прогон v1 и v1.1 с maxBarsInTrade=0 на одинаковом окне обязан дать идентичные метрики (это регрессионный тест патча).

Мотив: на 1h с тейком до ликвидности (ось C3) многодневные висяки почти гарантированы; инструмент лечения должен существовать до того, как этап 1 покажет проблему, чтобы не перепрогонять базу на v2.

## 5. Этап 0 (smoke-test) — выполнить после заливки

Чек-лист прогона на EURUSD 1h, короткое окно (~3–6 мес):
1. v1.1 c maxBarsInTrade=0 даёт метрики, идентичные v1 (регрессия патча).
2. Лимитки ставятся/снимаются по жизненному циклу зоны (Expired/Inverted/Filled).
3. Ни одного входа против тренда при trendMode=ema200.
4. strategy.exit активен с бара входа (нет сделок без стопа в списке трейдов).
5. Счётчики зон в таблице согласованы: создано = отфильтровано + истекло + инвертировано + отработано + активные.
6. Прунинг: нет ошибки переполнения массивов/боксов на длинном окне.
7. Смена mitigationMode wick↔close меняет статистику (не заглушка).

По каждому пункту — строка в README: pass/fail + комментарий. Fail любого пункта = фикс до этапа 1.

**Ограничение:** заливка в редактор TradingView — кликами (pine_new не работает). Не начинать заливку без подтверждения пользователя, что редактор свободен. Не перезаписывать открытый скрипт.
